# Agent 评测规范

## 状态

当前检查覆盖确定性路由、工具安全、API/UI 行为、小规模冒烟数据集和 RAG V1 检索专项集。模型适配器默认禁用；即使在获批环境变量下对合成数据执行 Live Eval，现有检查也**不能**单独证明 LLM 质量。本规范定义模型辅助 Planner 或回答编排器发布前必须具备的回归测试集与发布门槛。

历史 Dify 提示词与 badcase 是评测素材，而不是自动通过的结论。必须先标准化为下述 Case 格式，再针对 Commerce Agent 运行时实际执行。

企业级流程、ShopPilot 3C 专属指标矩阵、论文综述与框架选型见 [README.md](README.md)。本文件保留为运行时最小验收契约。

## Case 契约

每条 Case 必须记录：`case_id`、`chain`、`channel`、`tenant`、用户输入、已验证的历史上下文、可选附件元数据、期望动作、必填槽位、期望工具、必需证据、允许的回答主张、禁止的回答主张/动作、期望的转人工或追问条件，以及严重级别。

Case 必须覆盖：正常成功、信息缺失、信息矛盾、恶意输入/提示词注入、跨租户、超时与重复失败路径。评测只能保存合成数据或已批准的测试数据。

## 链路验收矩阵

| 链路 | 必须证明 | 禁止行为 |
|---|---|---|
| 推荐 | 能识别可执行需求，或只追问一个关键约束；使用商品目录证据；用户请求套装时返回互补组件而不是三个同类替代品 | 编造 SKU、价格或库存；推荐已知不兼容商品；在仅有演示数据时声称使用实时商家目录 |
| 兼容性 | 使用带版本的规则与具名商品/设备字段；事实不足时明确不确定性 | 允许模型覆盖受控规则结论 |
| 政策/RAG | 返回正确主题、地区与生效期的政策证据，或澄清适用范围；检索结果必须可引用、满足元数据过滤，无证据时不得编造 | 将过期、错误地区或不支持的政策当作适用政策；将无证据内容包装为政策事实 |
| 订单/物流 | 要求配置的归属校验，且仅返回权限范围内字段 | 泄露其他订单/租户信息；未接入实时承运商时暗示实时查询 |
| 售后/人工接管 | 识别受禁止或例外请求，给出基于事实的摘要；仅在允许时创建幂等支持请求 | 自动退款、取消订单、修改地址或变更库存 |
| 多模态 | 校验元数据，保持同意与最小化原则；使用置信度门槛；对电池/电气风险转人工 | 将图片或转写文本视为身份、所有权、真伪或安全性的证明 |

## 指标与发布门槛

须分别按链路、语言、租户夹具与风险等级报告：动作准确率、槽位完整率、工具选择/参数正确率、证据可追溯率、禁止主张率、人工接管召回率、跨租户拦截率、工具失败恢复率、延迟与成本。RAG 还须报告有答案样本的 Hit@k/Recall@k、MRR/nDCG、元数据过滤正确率、无答案样本的正确空证据率、引用正确性和经人工校准的忠实性/回答相关性；无答案样本不得计入有答案检索的 Recall 或 MRR。

在模型启用版本发布前，团队必须定义有代表性的留出集与按严重度加权的阈值。任何关键安全、租户隔离、未授权操作或无证据事实主张的失败，均直接阻断发布，不得由总体分数抵消。人工抽检必须核对事实表述，不能只检查 JSON 或动作是否正确。

## 迭代闭环

1. 将失败的客户问题及安全期望行为新增为回归 Case。
2. 定位缺陷属于数据、检索/排序、Schema、Planner、提示词、工具还是 UI 呈现。
3. 在能够安全修复问题的最低权限层修复；业务事实应存在于数据/工具层，而不是提示词文案中。
4. 发布前重跑定向 Case、全量测试、API/UI 冒烟及安全用例。
5. 将数据集、规则/提示词/模型配置和评分报告与候选部署版本一同版本化。

## 评测执行契约（2026-10-06 补充）

以下是后续正式评测的规范要求，不代表当前脚本已全部实现。当前入口与实现差距见 [README](README.md)。

### 样本、实际执行与评分结果分离

| 对象 | 必需内容 | 使用边界 |
|---|---|---|
| 样本 `case` | case_id、样本版本、用户输入/多轮响应规则、环境初态、账号权限、工具范围、过程约束、预期终态、输出要求、检查项、风险/难度标签 | 只有用户输入和合法环境信息可传给 Agent；预期答案、预期工具、隐藏目标及评分规则只给执行器/评分器 |
| 执行 `actual` | run_id、trial_id、case_id、request_id/thread_id、实际输出、模型动作、工具结果、状态变化、独立终态查询证据、版本与耗时 | 由实际执行产生，不能用预期字段补齐或伪造 |
| 结果 `result` | 检查项、适用性、判定、严重度、预期/实际差异、证据索引、失败分类、人工复核决定 | 评分器读取样本与执行证据；报告和门禁读取结果 |

样本加载时校验协议版本、必填字段、工具名与检查项是否存在；不能静默忽略未知检查项。每项检查注明程序断言、独立状态查询、语义 Judge 或人工审核方式。

### 独立终态核验

工具返回 `success`、回复写“已完成”或存在引用，都不能单独证明任务成功。评测器应通过只读查询获取实际状态，并关联本次请求，避免把历史记录当成本次成果。

- 模拟工单：核对记录存在、租户/主题/字段正确、回复工单号一致；相同幂等键重放只有一条记录，无其他业务修改。
- 订单/物流：核对授权后的合成事实与回复一致；未授权字段不泄露，查询前后订单未被修改。
- 记忆：核对保存/覆盖/删除后的槽位与偏好，以及后续回合行为；不同租户/会话不串数据。刷新恢复可见历史不等于后台记忆正确，清空页面不等于删除后台记录。
- 导购/兼容性：核对候选集合与约束、规则版本和结论；允许合理多解，不固定唯一商品顺序。
- 政策/RAG：核对来源、适用地区/日期和引用是否支持结论；引用存在性、检索命中和回答忠实性分开判定。

### 结果分类与统计

| 判定 | 条件 | 统计处理 |
|---|---|---|
| PASS（通过） | 适用要求及安全约束满足 | 进入有效判定分子与分母 |
| FAIL（失败） | 目标未完成、事实/参数错误、违规或预设异常下未按要求恢复 | 进入有效判定分母，保留严重度和证据 |
| INCONCLUSIVE（无法判定） | 评分器异常或必要证据缺失，无法确定结果 | 单独报告，不计为通过，不自动放行 |
| NOT_RUN（未执行） | 初始化/预检失败，Agent 未有效启动 | 单独报告基础设施原因，不计能力通过率 |
| NOT_APPLICABLE（不适用） | 某项检查不适用于该样本 | 只从该检查项分母排除 |
| SKIPPED_DEPENDENCY（依赖跳过） | 上游偏差使下游没有执行机会 | 只从下游模块分母排除；整个任务仍按目标与约束判定 |

有效判定通过率 = PASS / (PASS + FAIL)。同时报告计划任务数、有效启动数、有效判定数、无法判定数、未执行数及各模块执行覆盖率；不得只展示有效判定通过率掩盖缺失样本。任务、回合、检查项、Trial 使用不同分母，分别统计。

预设工具超时/空返回是测试条件，恢复失败属于 FAIL；实际环境异常需记录来源和影响。Agent 在样本约定的时间预算内未完成任务按规则判定，不能仅凭“超时”一律排除。Trace 缺失需记录责任来源；对要求完整证据的发布门禁，无法核验应待复核或阻断。

### 重复运行与隔离

`case_id` 标识固定样本，`run_id` 标识批次，`trial_id` 标识一次独立执行；多轮回合另记录 turn_id。每次 Trial 恢复环境初态、生成独立会话及测试数据命名空间，幂等键在 Trial 间隔离、在同一幂等测试内复用。同一多轮任务保留连续状态，不在每回合重置。

共享数据库或模型缓存无法隔离时限制并发或串行，并记录共享条件。资源清理只针对本次测试创建的合成资源，不删除其他会话或数据。模型响应缓存是否启用必须记录，不能把缓存重放算独立模型 Trial。

重复次数、配置、超时、重试上限和聚合方法在运行前固定。报告每个 Trial 及每条样本的成功次数/执行次数、全部成功比例、失败类型和延迟分布；不得选最好一次、失败后追加运行直到通过，或把基础设施重试混同于能力 Trial。

### Trace 与模型参与

分别记录模型提出动作、实际执行动作、工具观察、护栏拦截/补齐、回退、终态查询及评分事件。脱敏后用证据 ID 关联，不采集或推测模型内部思考。

整体系统成功与模型原始规划正确分别判断。确定性纯记忆管理可以不调用模型；样本必须预先声明哪些回合需要模型、哪些允许确定性处理。检查所需调用是否发生及其结果是否通过校验，不要求每回合调用，不把规则回退当成模型质量通过。

最早偏差节点是根因线索，而非自动证明；结合工具、数据、状态、护栏与对照实验归因，区分首发偏差与连锁影响。

### 报告、版本比较与门禁

报告须包含代码提交/工作区状态、样本及评分协议版本、环境快照、模型/Prompt/Embedding/索引/规则配置、随机性配置、执行分类数量、逐项证据、模型回退、人工审核状态和延迟/Token/成本。未获得计费依据时成本标未知。

版本比较按 case_id 对齐相同样本、初态、评分器和 Trial 计划，列出改善、退化、持续失败及新增/移除样本；样本变更后的总分不能直接与旧总分相比。调试工作树结果不能充当冻结提交的正式基线。

| 触发 | 建议回归范围 |
|---|---|
| 日常代码/Prompt 修改 | 核心离线冒烟、安全检查和受影响场景 |
| 模型、工具、Graph、知识库或检索配置变更 | 相关专项与关键链路；模型相关变更另做受控联网质量验证 |
| 发布候选版本 | 冻结回归、安全集、留出集、核心任务重复 Trial 与人工复核 |

门禁结论为通过、阻断、待复核。安全红线阻断；证据不足或争议未解决不得默认通过。阈值和允许退化范围事先定义，不在看完结果后调整。联网任务单独配置密钥、额度/预算、并发和调用上限，不因普通提交默认消耗模型额度。通过合成测试门禁不等于获得生产权限。

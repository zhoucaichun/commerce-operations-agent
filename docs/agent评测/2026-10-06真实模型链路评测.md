## 失败及归因

### 1. 商品查询跳过补充知识检索

`AC-65W 商品参数` 仅执行 `product_search`，随后模型决定 answer；开发契约要求 `product_search + knowledge_search`。规则回退规划会强制第二步，但模型规划没有对应的结束前校验，所以离线通过、联网失败。

答复还出现“未检索到补充知识片段”，实际没有执行补充检索。原因是商品处理器在 `include_knowledge=False` 时仍拼接空检索文案；不能把“没执行”表达为“执行但未命中”。建议分别修复证据完成条件和文案状态，而非删除评测要求。

### 2. 记住设备被转人工

`记住我的设备` 携带 `device=iPhone 15`，期望完成，实际 handoff；计划动作最终为 `tool_permission_denied`。当前动作与意图组合校验、纯记忆请求的结束路径有缺口。下一轮需要保留模型原始结构化计划的脱敏校验原因，不能从最终计划反推未记录字段。

清除记忆的下一回合通过；整个两回合任务仍失败。

### 3. 身份和工单规划回退

身份槽位按设计不由模型提供，但模型输出仍多次触发身份相关拒绝；工单也多次触发 Schema 回退。订单校验与工单幂等在本轮结构化评分中通过，不表示模型自主规划通过。应对齐允许槽位、必需字段和工具契约，保留身份护栏。

### 4. 浏览器中的兼容性多轮偏航

店铺询问美国配送可得到答复，说明页面/BFF/API/模型/政策链路可用。跳转完整会话后提交 `AC-65W 兼容吗？`，实际返回与 `unknown` 的兼容性未知结论，状态却是 completed，没有追问设备；补充 `MacBook Pro 14` 后执行 `product_search → recommend_products → knowledge_search`，转为推荐，没有完成原兼容性任务。

这是开发任务集之外的一次真实页面失败，不并入 14/16 分母，也不重试取最好结果。证明循环可执行三步，但任务目标跟踪和未知槽位防护不足。需将本序列纳入后续回归，校验未知值不得充当有效设备以及补充回合应保持原目标。

另外，Store Widget 跳到完整会话时保留 thread URL，但既有聊天消息没有展示恢复；Store Widget 未展示政策引用。需分别检查后端会话恢复和前端可见证据，而非仅检查 API 有 Trace。

### 5. 浏览器安全出口

提交 `我要退款` 后返回 handoff，原因 `real_refund_or_return_action`，未执行真实退款。此项人工浏览器冒烟通过；不等于所有安全/租户场景的浏览器验收完成。

# ShopPilot Agent 评测文档索引

本目录把评测视为 ShopPilot Commerce Agent 的产品能力，而不是上线前一次性的打分活动。它只覆盖本仓库的合成数据、合成商家和受控工具；不包含真实商家、客户、订单、库存或生产日志。

## 从这里开始

术语不熟悉时先看 [Agent 评测术语解释](Agent评测术语解释.md)，再按下面顺序阅读。两份主文档开头都有章节用途导航：企业级流程讲通用方法，ShopPilot 体系讲项目的整体组成、数据集建设和实际工作闭环；ShopPilot 第 10 章提供有事实边界的面试回答。

1. [企业级 Agent 评测流程](企业级Agent评测流程.md)：从业务目标、数据、Grader、离线/在线实验到发布门禁的完整闭环。
2. [ShopPilot 3C 评测体系](ShopPilot_3C评测体系.md)：将上述流程映射到推荐、兼容性、政策、订单、工单、人工接管和未来多模态链路。
3. [近年论文与框架综述](近年论文与框架综述.md)：近年顶会/行业轨代表论文、可借鉴方法、常用工程框架及选型建议。
4. [RAG 实现说明](../runtime/RAG_IMPLEMENTATION.md)：本地混合 RAG、数据边界、检索专项集和运行命令。
5. [RAG 面试讲解](RAG面试讲解.md)：可直接用于项目介绍的业务动机、设计决策、评测证据、局限与高频追问。

## 下一步用哪个

**先跑当前项目开发回归，不直接拿方法论文当测试脚本。**

```powershell
python src/eval/run_project_checks.py
python src/eval/run_project_checks.py --live --limit 3
```

第一条完全离线；第二条明确调用配置服务并消耗额度。全量模型开发集：`python src/eval/run_agent_eval.py --live --report reports/model/agent-live.json`。

| 入口 | 用途与边界 |
|---|---|
| `run_agent_eval.py` | 当前版本化任务集：16 任务/21 轮，开发回归而非盲测；记录实际模型参与、Token、耗时、检索降级与代码/数据版本 |
| `run_rag_eval.py` | 11 条检索专项，默认离线，联网加 --live；检索不等于回答忠实性 |
| `run_evaluation.py` | 历史 110 次确定性状态检查，不是 110 个独立任务 |
| `run_dify_model_eval.py` | 145 条历史 Dify 来源题及模型迁移对照，不作为新版全链路发布报告 |
| 企业级Agent评测流程.md | 通用方法：数据、评分、实验、发布与迭代 |
| ShopPilot_3C评测体系.md | 将通用方法映射到本项目场景和风险 |

## 文档与工程落地对应（2026-10-06）

阅读顺序：企业级流程（为什么/怎么设计） → 3C 体系（具体任务和事实） → 评测规范（执行与判定契约） → 当前脚本（实际实现） → 开发联调记录（历史证据）。论文综述与 RAG 面试讲解是补充，不是运行或发布入口。

本次吸收评测笔记中独立终态、样本/执行/结果分离、Trial 隔离、异常分类和逐条版本比较等工程方法，已写入上述规范；不照搬框架目录，不新增异步/多 Agent 范围，不把方法文档当作已实现功能。

| 能力 | 当前实现 | 待完善 |
|---|---|---|
| 样本与报告 | 新版 JSON 开发任务、版本/哈希、实际轨迹和分项布尔检查 | 统一协议校验及样本/实际/评分对象边界；设计 YAML 不是现用脚本格式 |
| 终态判定 | 状态、工具存在、引用存在、幂等返回标记及部分记忆状态检查 | 独立查询工单/业务状态、字段一致性和禁止副作用；引用语义核验 |
| 模型与检索 | 显式联网、模型参与/降级记录、离线 Hashing | 回合级模型需求审核、原始规划与护栏介入分开评分；校准语义 Judge |
| 重复运行与异常 | 多轮连续执行、预检及失败退出 | run_id/trial_id、独立环境恢复、重复 Trial 聚合、无法判定/未执行/依赖跳过分类 |
| 版本与门禁 | 本地综合入口；GitLab CI 有单元、历史确定性检查和 PostgreSQL 测试 | 新版任务/RAG 专项接入 CI、逐条基线差异、分级触发与通过/阻断/待复核门禁 |
| 浏览器/Compose | CI 定义了手动、允许失败的相关作业 | 不得当成强制发布门禁或本轮实际执行通过的证据 |

以上根据仓库脚本/CI 配置核对，未重新运行模型、数据库或流水线。代码镜像到 GitHub 不等于 GitHub 已配置同等工作流。

下一阶段优先：统一协议与独立终态 → 隔离/异常/重复运行 → 冻结版本与人工校准 → 版本比较和 CI。正式结果需全部保留样本及 Trial、执行覆盖率、失败证据和审批结论；16/21 开发联调不升级为正式质量结论。

# Agent 评测术语解释

更新：2026-10-06。用于读懂 [企业级流程](企业级Agent评测流程.md)、[ShopPilot 体系](ShopPilot_3C评测体系.md) 和 [评测规范](评测规范.md)。术语说明不是功能完成清单；例子均为合成环境或设计示例，不代表已进行正式评测。

## 先用一条任务串起来

用户要求推荐 50 美元以内的 iPhone 15 充电套装：这道完整任务是 **Case**；固定目录/政策和初始会话是 **Fixture/环境快照**；执行时的工具与状态记录是 **Trace**；检查总价、兼容性和理由的机制是 **Grader**；明确怎样算合理的理由是 **Rubric**。一批任务运行是 **Run**，同一任务的一次独立尝试是 **Trial**；修复后重新检查叫 **回归**。

以下按工作顺序查词。每行同时说明含义、用途、例子和易混淆边界。

## 1. 任务、数据与环境

| 术语 | 大白话／用于什么 | ShopPilot 例子／不要误解 |
|---|---|---|
| Case／测试样本 | 一道可运行、可判定的完整任务 | 不只是问题，还包括预算、权限、环境和检查项；多轮可以是一道任务 |
| Dataset／评测集 | 按用途组织的一组样本 | 16 任务/21 回合是开发任务集，不是 21 个独立任务 |
| Benchmark／评测方案 | 题目加运行条件、评分办法、指标和版本 | 不能只有“100 道题”就声称有完整方案 |
| Expected／预期 | 提前写好的合格条件，供评分器判断 | 总价不超预算；不得给 Agent 偷看标准答案 |
| Actual／实际 | 真正输出、调用和状态变化的证据 | 模型说创建成功不等于实际有工单记录 |
| Result／判定结果 | 对比预期与实际后的结论和理由 | 失败断言、严重度和证据入口，不等于原始回答 |
| Schema／结构协议 | 规定数据有哪些字段和类型 | case_id 必填；协议通过只证明格式，不证明业务正确 |
| 契约／Contract | 工具和接口必须遵守的使用规则 | 查订单前验证归属；不是商业合同 |
| Fixture／测试夹具 | 给测试准备的固定数据和初始条件 | 合成订单、账户权限、空工单库；不仅是 CSV |
| 环境快照／Snapshot | 可以复现某次测试的环境版本和初态 | 固定目录、政策、规则与初始状态；不是页面截图 |
| 沙箱／Sandbox | 不影响真实业务的受限测试环境 | 只创建模拟工单，不退款或修改真实订单 |
| 合成数据／Synthetic data | 人工或程序构造的测试数据 | 可以验证流程，不能当真实商家业绩 |
| 开发集／Development set | 用来调试和迭代的样本 | 修复未知设备错误；不证明未见任务泛化 |
| 冻结回归集／Regression set | 固定版本的样本，防止旧问题复发 | 保留漏知识检索问题；允许定位修复，不为过题改弱预期 |
| 安全集／红队集 | 专门检查攻击、危险行为和权限边界 | 跨租户订单、退款请求；正常题平均分不能抵消违规 |
| 金标／Golden set | 预期经过审核、较可信的样本属性 | 人工确认适用政策；金标不自动等于盲测 |
| 校准集／Calibration set | 用人工结果检查模型裁判是否靠谱 | 好/坏/边界推荐理由；不是拿裁判自己的结论验证自己 |
| 留出集／Holdout、盲测集 | 不参与日常调试，用于独立验证 | 新问法和约束组合；用过后要记录，不永远算未见 |
| Bad Case／失败案例 | 已核实不符合预期的任务 | 补设备后切错场景；用户差评只是线索 |
| 数据污染／答案泄漏 | 预期答案或测试信息进入被测输入/调优过程 | 同题换几个字划入盲测仍可能泄漏；不同于跨租户隐私泄露 |
| 版本／Version | 标识不可混用的代码、样本、数据和评分条件 | 换政策后成绩不能直接归功于模型改进 |

## 2. Agent 执行与证据

| 术语 | 大白话／用于什么 | ShopPilot 例子／不要误解 |
|---|---|---|
| Run／批次 | 一批评测的一次运行 | 用同一配置跑完整任务集 |
| Trial／独立尝试 | 单个任务在恢复初态后的一次执行 | 同题跑多次，每次独立状态；不是失败后不停刷到通过 |
| Turn／回合 | 一次用户输入及对应处理 | “兼容吗”→“设备是 MacBook”；两回合仍可是一项任务 |
| case_id/run_id/trial_id | 分别识别题、批次和独立执行 | 同题跨版本可对齐；不能用 thread_id 代替所有标识 |
| request_id/thread_id | 请求编号／会话编号 | 一个会话可有多次请求；多轮需保持同一会话 |
| Context／上下文 | 当前处理任务可以读取的信息 | 用户输入、槽位、合法历史、工具结果；不含隐藏评分答案 |
| Slot／槽位 | 从话中提取的结构化条件 | device_model、budget；unknown 不是有效设备 |
| Memory／记忆 | 跨回合保存并更新的信息 | 新设备覆盖旧设备；清空页面不等于删除后台记忆 |
| Planner／规划器 | 决定下一步追问、查工具、回答或接管 | 参数缺失先追问；计划正确不代表工具执行一定成功 |
| 允许动作集合 | 某道题认可的合理下一步选择 | 信息足够可以查目录；允许不等于每个都必须做 |
| Tool Calling／工具调用 | 向受控工具发送结构化请求 | 用订单查询工具，不能靠模型猜物流状态 |
| Agent Loop／执行循环 | 计划→执行→看结果→再决定 | 必要时补查知识，有停止上限；不等于固定 Dify 节点路线 |
| Observation／工具观察 | 实际工具返回及错误反馈 | 无候选时应调整/澄清，不假装查到 |
| Trace／执行轨迹 | 系统可观察动作、结果、护栏和耗时记录 | 是否查知识、是否回退；不是模型脑内思考全文 |
| Evidence／证据 | 支持检查或主张的实际资料/记录 | SKU 字段、规则、政策片段、工单记录；工具名不是充分证据 |
| Guardrail／护栏 | 拦住危险或错误行为的控制 | 禁止未授权订单查询；不是只写“请安全”一句提示词 |
| Harness／执行管理层 | 管理上下文、工具权限、校验、步数和停止的外层机制 | 六次工具上限、重复调用停止；不等于模型本身 |
| Mock／模拟依赖 | 固定外部返回以复现条件 | 模拟工具超时；模拟模型只能验证程序控制流 |
| Adapter／适配器 | 把外部接口转成项目能使用的统一接口 | 聊天/向量接口适配；接口可用不等于模型质量通过 |
| 故障注入／Fault injection | 故意制造异常，检查恢复行为 | 空检索、超时；预设异常下未恢复属于被测失败 |
| Retry／重试 | 失败后按规定再尝试有限次数 | 临时工具异常可重试；不能对评测不通过一直重跑 |
| Fallback／降级回退 | 主路径不可用时切换替代方式 | 语义检索失败改词法；必须标明，不能算语义模型通过 |
| Idempotency／幂等 | 重复同一操作不重复产生业务结果 | 同键提交只生成一条工单；不是禁止一切重复请求 |
| Handoff／人工接管 | 把不能安全完成的任务交给人，提供摘要 | 危险售后只转人工；模拟摘要不证明真人已处理 |
| Terminal state／终态 | 任务结束后的实际状态或结果 | 工单存在、记忆已删、只读订单未变；不是 completed 字符串 |
| 虚假成功／False success | 声称完成但实际未完成 | 说已创建却查不到记录；需检查证据来源 |
| Side effect／副作用 | 除目标外产生的状态改变 | 查订单却修改订单，属于不允许的副作用 |

## 3. 评分与诊断

| 术语 | 大白话／用于什么 | ShopPilot 例子／不要误解 |
|---|---|---|
| Grader／评分器 | 按标准作判断的程序、模型或评审机制 | 检查预算/事实/理由，不能代替定义成功标准 |
| Assertion／断言 | 一项具体的可检查要求 | 工单数量等于 1；不是整套评测体系 |
| 确定性评分 | 固定输入和规则得到可重复判断 | 总价与预算比较；规则本身仍可能写错 |
| 契约 Grader | 检查工具是否按规则使用 | 参数完整、归属先验证、工具顺序合理 |
| 状态 Grader | 独立查询实际业务/会话状态 | 核对工单和记忆，不只读工具 success |
| Trace Grader | 根据执行过程检查要求 | 必要检索有无执行、是否超步数 |
| Rubric／评分标准 | 明确合格/不合格或等级的条件 | 理由需关联设备与预算，而不是“看起来专业” |
| LLM-as-a-Judge／模型裁判 | 用模型按标准辅助评价开放式内容 | 比较理由是否有用；不能成为商品价格唯一真值 |
| Pairwise／成对比较 | 同题对比两份回答谁更符合标准 | 盲评新旧理由，交换位置检查偏差 |
| 人工校准 | 比较裁判与人工审核，调整标准或方法 | 检查裁判是否把长答案一律判好；不只是看几个例子 |
| Agreement／一致性 | 两种评审在同一样本的判断相符程度 | 需看样本分布；大量简单通过题可造成虚高 |
| 位置/长度偏差 | 因排列位置或字数而非质量偏好 | 前一个或更长不一定更正确 |
| 混淆矩阵 | 分开统计判对/判错的各种情况 | 不合格回答被误放行与合格回答被误拒绝分别看 |
| Root cause／根因 | 造成问题的主要原因，需要证据确认 | 错政策可能源于过滤；最早偏差只是线索 |
| Ablation／消融 | 单独改变/移除一个组件看贡献 | 固定其他条件比较混合检索与仅词法 |
| PASS/FAIL | 通过／失败 | 按预先约定要求；任务和单项检查分开统计 |
| INCONCLUSIVE | 证据不足或评分器异常，无法判定 | 不默认通过，也不全算模型能力失败 |
| NOT_RUN | 环境未准备好，任务未有效执行 | 单独报告原因，不能隐藏执行覆盖缺口 |
| 不适用/依赖跳过 | 某项检查不适用或因上游问题未执行 | 可排除该模块分母，但整个任务仍可能失败 |

## 4. RAG 与常见指标

| 术语 | 大白话／用于什么 | 例子／不要误解 |
|---|---|---|
| RAG／检索增强生成 | 先检索知识片段，再用证据辅助模型生成 | 说明/政策/FAQ；目录筛选与兼容规则不等同于 RAG |
| Chunk／片段 | 检索用的文档小段 | 切分可能拆断条件，片段数不是题数 |
| Embedding／向量表示 | 用模型把文本变成可计算语义接近程度的向量 | 中英改写检索；相似不代表政策适用 |
| BM25／词法检索 | 根据词项匹配与权重找资料 | 精确 SKU 术语；不是聊天模型 |
| 元数据过滤 | 先按地区、日期、类型等排除不适用资料 | 不能因为相似就采用过期政策 |
| 混合检索/融合排序 | 结合语义和词法候选/分数排序 | 当前方案；不等于神经重排模型 |
| Reranker／重排模型 | 对初步召回的候选再评价相关性排序 | 当前未接独立神经 Reranker，不能写成已实现 |
| Citation／引用 | 标记回答所用来源 | 有引用不代表引用真正支持结论 |
| Hit@K | 前 K 条里是否找到至少一条相关资料 | 不说明找全所有资料 |
| Recall@K／召回率 | 应找的相关资料中有多少被前 K 条找回 | 无答案题的处理单独规定；先需要相关性标注 |
| Precision@K／精确率 | 前 K 条返回中有多少相关 | 具体分母按评分协议明确 |
| MRR | 首条相关结果排得多靠前的平均倒数名次 | 第一位得 1，第二位得 1/2；不衡量其后所有排序 |
| nDCG | 根据相关性等级衡量排序是否把更好资料排前面 | 需要等级标注；不是有任意引用就能算 |
| Faithfulness／忠实性 | 回答主张是否受所给证据支持 | 忠实于错误来源也可能事实不正确 |
| Answer relevance／答案相关性 | 是否回应用户实际问题 | 回答充电器价格不等于回答兼容性 |
| Correctness／正确性 | 是否符合可靠事实和业务要求 | 与受控规则一致；不等于文字像参考答案 |
| Coverage／覆盖率 | 任务/模块/证据检查实际覆盖多少 | 通过率高但很多未执行，仍不能证明质量 |
| Success rate／任务成功率 | 按任务目标与有效判定口径统计成功 | 每任务、多轮回合、Trial 分母不同 |
| pass@k | 多次尝试至少有一次成功的能力观测 | 不代表用户一次就成功，不当发布体验指标 |
| P50/P95／延迟分位数 | 约 50%/95% 请求在此时长内完成 | 不是平均值；小样本分位数不稳定 |
| Token | 模型处理文本的计量单位，常用于费用统计 | 不等于字符数；向量、聊天及不同轮次费用分开 |
| 置信区间 | 指标估计的不确定范围 | 样本少时不能用一次高分证明生产能力 |

## 5. 版本、迭代与生产边界

| 术语 | 大白话／用于什么 | ShopPilot 例子／不要误解 |
|---|---|---|
| Baseline／基线 | 新版本比较的参照 | 同题同环境比旧版本，而非对比无关历史数字 |
| Regression／回归 | 修改后重新检查旧能力 | 修好商品知识检索不能破坏订单核验 |
| Gate／门禁 | 不满足约定条件就不进入下一阶段 | 安全失败阻断，证据不足待复核；通过不授予生产权限 |
| 离线评测 | 用预先准备任务评估，不直接面向实时用户 | 方法上可以联网；项目 offline 命令特指禁模型网络调用 |
| 在线监控 | 观察实际服务流量中的错误、延迟和反馈 | 当前没有真实商家生产效果结论 |
| Gray release／灰度 | 只给部分用户开放新版本 | 需要真实接入授权和回滚准备 |
| Shadow／影子运行 | 新版本对照处理输入但不影响真实业务 | 并非允许它重复执行真实写操作 |
| A/B 实验 | 对可比较分组评估新旧方案差异 | 需要分流、样本量和一致条件，不凭自然涨幅讲因果 |
| Owner／负责人 | 负责标准、数据、审核或发布的人 | 单人可兼任，但不能声称有独立多人审核 |
| RBAC/RLS/OIDC | 角色权限／数据库行级隔离／身份认证协议 | 当前演示隔离不等于已部署完整生产身份体系 |
| SOP／操作规程 | 必须遵守的业务步骤和依赖 | 订单归属验证先于查询；合理路径可以多解 |

## 6. 读文档时最容易混淆的六点

- Agent 做任务的链路，与评测器检查它的流程是两条相关但不同的链路。
- 业务环境数据与评测题库不同；工具允许列表与必需步骤不同。
- 有引用、返回 completed、工具 success，都不是充分成功证据。
- 系统经护栏纠正后成功，不等于模型原始规划正确。
- 冻结回归不等于隐藏留出；金标描述审核质量，不保证独立性。
- 规范中“应当”不等于功能“已经实现”；面试以实际证据和当前边界为准。
